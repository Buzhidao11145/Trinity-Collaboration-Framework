## 概述

Trinity 是一个方法论框架，用于组织和管理AI辅助的安全研究任务。它定义了**决策者（人）→ 规划者（推理AI）→ 执行者（行动AI）** 的三层协作模型，以及一套完整的任务闭环流程。

Trinity的设计理念：**方法论应该是AI可读、可执行的**。框架的全部知识资产以标准Markdown格式组织，任何AI都能理解和使用。

---

## 核心思想

### 三层角色定义

| 角色 | 谁 | 职责 |
|:-----|:---|:------|
| **决策者** | 人 | 下达指令、审批方案、确认产出 |
| **规划者** | 高推理能力AI | 理解意图、设计方案、分配任务 |
| **执行者** | 高行动能力AI | 执行任务、验证产出、归档记录 |

**职责边界不可混淆。** 执行者不自行改变方案，规划者不越权决策。

### 六步闭环流程

```
① 想法 → ② 确认 → ③ 方案 → ④ 指令 → ⑤ 验证 → ⑥ 归档
```

任一任务必须走完六步才能视为完成。**不归档 = 任务未完成。**

### 缓冲层机制

高风险操作前插入5条检查项：

1. 这个操作在授权范围内吗？
2. 这个操作是否涉及高危操作（写远程系统、改密、删数据）？
3. 是否有替代方案？
4. 是否保存了当前状态（可回滚）？
5. 是否需要通知决策者？

**任意一项为"是" → 等待决策者审批。**

## 核心组件

### 知识仓库

8个子目录，覆盖完整知识生命周期：

| 目录 | 用途 |
|:-----|:------|
| `daily/` | 每日操作日志 |
| `capabilities/` | 全局能力清单 |
| `learning/` | 学习成果记录 |
| `decisions/` | 决策知识库 |
| `pulse/` | 脉搏日志 |
| `tasks/` | 任务摘要 |
| `templates/` | 标准化模板 |
| `skills/` | AI可读的技能文档 |

### 决策知识库

13条经过实战验证的决策规则，涵盖：
- **API调试** — 参数名排查、空值验证
- **文件操作** — 原版确认、大小校验、ditto操作
- **分析方法** — 静态分析优先、代理模式优先
- **安全审计** — 硬编码凭证排查、安全响应模式
- **批量处理** — 逐阶段try-catch
- **流程管控** — 硬约束优先、注入方案选择

每条规则标注来源背景、验证状态、严重程度和操作模板。

## 快速开始

```bash
# 1. 克隆仓库
git clone https://github.com/your-org/trinity-framework.git

# 2. 阅读核心原则
cat trinity-framework/核心原则.md

# 3. 使用模板启动第一个任务
cp trinity-framework/templates/任务提示词模板.md ./my_first_task.md

# 4. 参考决策规则库避免常见错误
cat trinity-framework/decisions/决策知识库.md
```

**前置条件：** 能够读取标准Markdown文件的AI系统（如Claude、GPT系列、DeepSeek等）。
