# 自主学习机制

> **本文件已脱敏处理。**
>
> **用途：** 详细阐述 Trinity 框架的自主学习机制——触发条件、探索流程、验证机制、成果沉淀方式
> **所属：** Trinity 框架设计文档

---

## 概述

自主学习机制让 Trinity 系统在决策者不介入的情况下，持续探索、验证和沉淀知识。这不是"AI 自己干活"，而是"AI 在得到允许的范围内，主动学习和维护知识体系"。

---

## 触发条件

| 条件 | 优先级 | 说明 | 示例 |
|:-----|:------:|:------|:------|
| **空闲时段** | 🟢 低 | 决策者超过 30 分钟未交互 | 利用碎片时间整理知识索引、更新能力清单 |
| **任务失败** | 🔴 高 | 同一任务连续失败 2 次以上 | 自动触发失败分析流程，搜索解决方案 |
| **知识缺口** | 🟡 中 | 规划者发现当前知识不足以支持某个任务方向 | 标记知识缺口，在空闲时研究填补 |
| **新发现** | 🟡 中 | 执行者在任务中发现了计划外的新技术点 | 验证新技术点的可行性，沉淀为能力 |
| **定期复盘** | 🟢 低 | 每周固定时间的系统性检查 | 检查所有知识库的完整性，补充遗漏 |
| **外部更新** | 🟢 低 | 环境变化、工具版本更新等 | 检查依赖工具的最新版本，评估影响 |

## 学习闭环

```
触发条件
    ↓
┌─────────────────────────────────────────┐
│              探索                        │
│  · 搜索相关资料                         │
│  · 查看待解决问题列表                   │
│  · 测试新方法/工具                      │
└────────────────┬────────────────────────┘
                 ↓
┌─────────────────────────────────────────┐
│              验证                        │
│  · 在安全环境确认可行性                 │
│  · 至少成功 2 次才算验证通过            │
│  · 记录验证过程和结果                   │
└────────────────┬────────────────────────┘
                 ↓
┌─────────────────────────────────────────┐
│              沉淀                        │
│  · 更新决策规则                         │
│  · 更新能力清单                         │
│  · 更新学习记录                         │
│  · 通知决策者（可选，按重要性决定）     │
└────────────────┬────────────────────────┘
                 ↓
          等待下一个触发条件
```

## 执行者的自主学习

### 研究范围

执行者在空闲时会自动：

1. **检查待解决问题列表**，从优先级最高的开始研究
2. **搜索相关资料**（技术文档、源码分析、社区讨论）
3. **在安全环境中测试和验证**新发现
4. **将验证通过的知识沉淀**到决策知识库或能力清单中

### 自主学习的产出

| 产出类型 | 说明 | 存放位置 |
|:---------|:------|:---------|
| 新技术笔记 | 发现的新技术或新工具的研究记录 | `learning/` |
| 决策规则草案 | 待决策者审核的新规则 | `decisions/`（标记为草案） |
| 能力更新 | 现有能力成熟度的调整 | `capabilities/` |
| 待决问题 | 需要决策者判断的问题 | 标记后等待决策者交互 |

### 自主学习的边界

自主学习不是无限度的。执行者**不能**：

- 访问未经授权的系统或数据
- 执行可能影响系统稳定性的操作
- 在决策者未审批的情况下修改核心配置文件

## 规划者的自主学习

### 研究方向

| 方向 | 说明 |
|:-----|:------|
| **规则提炼** | 从已有任务摘要中识别模式，提炼为新决策规则 |
| **知识关联** | 发现知识仓库中的知识孤岛，建立关联关系 |
| **缺口识别** | 分析当前知识无法覆盖的场景，标记为探索方向 |
| **流程优化** | 检查已有流程的效率，提出简化或优化建议 |

### 主动性界限

规划者在自主学习中的主动程度分为三级：

| 级别 | 行为 | 是否需要审批 |
|:-----|:------|:------------:|
| 🟢 **被动等待** | 只在决策者提问时回答问题 | 否 |
| 🟡 **观察建议** | 识别模式后向决策者提建议，但不主动探索 | 否 |
| 🟠 **主动探索** | 在空闲时研究知识缺口 | 是（需要决策者明确允许） |
| 🔴 **自主行动** | 未经通知直接修改知识仓库 | **从不允许** |

## 成果沉淀标准

| 成果类型 | 沉淀条件 | 格式要求 |
|:---------|:---------|:---------|
| 决策规则 | 至少验证 2 次成功 | 触发条件 + 决策建议 + 来源说明 + 严重程度 |
| 能力更新 | 实战验证通过 | 成熟度评级 + 用途说明 |
| 学习记录 | 任何值得记录的教训 | 问题描述 + 根因 + 学习要点 + 相关规则 |
| 技能封装 | 操作流程标准化 | 触发条件 + 流程 + 输入输出 + 排查清单 |

## 与知识仓库的交互

```
自主学习触发
    ↓
读取知识仓库（了解已有知识，避免重复工作）
    ↓
探索新领域（研究、测试、验证）
    ↓
验证通过后写入知识仓库（更新规则、清单、记录）
    ↓
生成学习摘要（供决策者审阅）
    ↓
等待下一次触发
```

## 长期价值

> 一年后回头看，知识仓库里不只是完成了哪些任务，还有学到了哪些知识、发现了哪些规律、积累了多少可复用的 Skill。

每天一小点自主学习的累积效果：

| 时间跨度 | 预期累积成果 |
|:---------|:-------------|
| 1 周 | 3-5 条新的决策规则，知识仓库结构完整 |
| 1 月 | 10-15 条规则，2-3 个新技能，能力覆盖范围扩大 |
| 1 年 | 50+ 条规则，10+ 个技能，完整的知识体系 |
